DeepSeek V4 Flash 0731 正式版を数日間がっつり使ってみたので、長所と短所をまとめる。

## 長所その一：安い。異常なくらい安い

汚れ仕事も重労働も全部これに丸投げできる。一切の心理的負担なし。使うだけで儲けもの——節約できた時間の価値で、さらにトークンが買えるレベル。

どれくらい安い？私の実感だと：バッチ処理、Agent ループ、何十ターンもの会話を回しても、請求書はほぼ無感覚。AI で一番高いのは計算リソースじゃなくて、「使うのをためらう」という心理的ハードル。V4 Flash はその門を文字通りぶち壊した。

## 長所その二：速い

これはめちゃくちゃ大事。2 時間かかったタスクを待ってから検収するなんて、誰もやりたくないだろう。

Flash モデルの実感は電光石火、口に出せば叶う。コード書き、バグ修正、テスト、バッチ処理、フィードバックが即時で返ってくる。特に Agent のツールループと組み合わせると、どのステップも数秒以内に完結して、インタラクションの体感が全然違う。

## 長所その三：コンテキストが長い

1M のコンテキストなら、大抵の複雑なタスクが丸ごと入る。しょっちゅう compact する必要がない。

前は短いコンテキストのモデルだと、コードベースをちょっと見ただけで満杯になって、あれこれ圧縮テクニックでスペースを節約してた。今はリポジトリ丸ごと、ドキュメント一式、会話履歴全部をぶち込んでも、まだ収まる。キャッシュ割引も合わせれば、長文コンテキストのシーンをめちゃくちゃ安くできる——重複コンテンツはキャッシュにヒットして、値段が半額どころじゃないくらい下がる。

## 長所その四：公式組み込みの Web 検索

公式 Responses エンドポイントにサーバーサイド web-search が内蔵されていて、設定なしでそのまま検索サービスが使える。

鮮度が命のコンテンツや Agent の調べ物シーンにはモチベーション必須級。検索エンジンに自分で繋がなくても、Search Key 申請も不要。公式がフロー全体をホスティングしてくれる。詳しくはこの記事：[DeepSeek API に組み込みの Web 検索、Responses API で公式の検索能力をタダで使う](/blog/deepseek-api-web-search)

## 長所その五：オープンソース、ベンダー非依存

モデルサービス事業者はどれでも選んで、デプロイや再販ができる。ベンダー依存の心配がない。

閉鎖系ベンダーの可哀想な Reset 施しを祈る必要もない。オープンソースはエコシステムを意味し、選択肢を意味し、モデルを自分の製品に組み込んでも首を絞められないことを意味する。

## 短所：マルチモーダル非対応

画像を読む、見る系のシーンに制約がある。でもこれは「安さ」の必然的な代償だ——マルチモーダルにするとモデルのパラメータが膨らみ、コストが上がる。

解決策は簡単：**組み合わせて使う**。画像認識が要るときは専用のビジョンモデルに画像を渡し、テキスト推論はそのまま V4 Flash。いま最もコスパがいい識図（きず）スキームを調べたので、こちら：[DeepSeek にマルチモーダルを補う：Qwen-3.7-Flash 識図スキーム](/blog/qwen-vision-for-deepseek)

## 私の結論

V4 Flash は「日常の主役」級のモデルだ：安くて使い放題、速くて文句なし、コンテキストがでかくて節約不要、おまけに検索付き。

チームで働くとき、汚れ仕事は全部こいつに投げて、視覚が必要なときは横に識図モデルを置いて連携技を出す。このコンビネーション打ちなら、コスト低・体験良・どのベンダーにも縛られない。
