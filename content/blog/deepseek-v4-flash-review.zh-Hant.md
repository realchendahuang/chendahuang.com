深度體驗了幾天 DeepSeek V4 Flash 0731 正式版，總結一下它的優缺點。

## 優點一：便宜，極度的便宜

便宜到髒活累活可以全都交給它做，完全沒有任何心理負擔。用了就是賺到——省下來的時間價值，都能買更多 Token 了。

有多便宜？我的使用體感是：跑批次處理、跑 Agent 迴圈、跑幾十輪對話，帳單幾乎無感。AI 最貴的不是算力，是「不敢用」的心理門檻。V4 Flash 直接把這道門拆了。

## 優點二：速度快

這是很重要的一點。你也不會希望一個任務跑兩個小時才回來驗收吧？

Flash 模型給我的體感就是快如閃電、言出法隨。寫程式、改 bug、跑測試、批次處理，回饋都是即時的。尤其是搭配 Agent 工具迴圈，每一步都在幾秒內完成，互動體驗完全不一樣。

## 優點三：上下文長

1M 的上下文，可以容納大多數複雜的任務，不需要頻繁 compact。

以前用短上下文模型，程式碼庫看幾眼就滿了，得靠各種壓縮技巧省空間。現在直接把整個儲存庫、整批文件、完整對話歷史丟進去，它還裝得下。搭配 Cache 打折，長上下文場景可以做到非常便宜——重複內容命中快取，價格直接砍半以上。

## 優點四：官方內建聯網搜尋

官方 Responses 介面內建了伺服器端 web-search，不用任何設定，直接享有搜尋服務。

對時效性內容、Agent 查資料的場景，這是剛需。不用自己接搜尋引擎、不用申請搜尋 Key，官方託管整個流程。詳細介紹見這篇：[DeepSeek API 內建聯網搜尋，Responses API 白拿官方搜尋能力](/blog/deepseek-api-web-search)

## 優點五：開源，不綁定供應商

你可以選擇任何一家模型服務商來部署或轉售，不用擔心供應商綁定。

不用再去祈禱某些閉源廠商可憐的 Reset 施捨。開源意味著生態、意味著選擇權、意味著你能把模型嵌入自己的產品，不會被掐脖子。

## 缺點：不支援多模態

讀圖、看圖的場景有侷限。但這是「便宜」的必要代價——多模態會讓模型參數膨脹，成本就上去了。

解法也很簡單：**組合使用**。需要辨識圖片的時候，把圖片交給專門的視覺模型處理，文字推理繼續用 V4 Flash。我研究了目前 CP 值最高的識圖方案，見這篇：[給 DeepSeek 補上多模態：Qwen-3.7-Flash 識圖方案](/blog/qwen-vision-for-deepseek)

## 我的結論

V4 Flash 就是那種「日常主力」等級的模型：便宜到隨便用、快得沒話說、上下文大到不用省、還帶搜尋。

團隊裡幹活，髒活累活全丟給它；需要視覺的時候，旁邊配一個識圖模型組合出招。這套組合拳打下來，成本低、體驗好、不綁死任何一家。
