> اصل استدلال اولین بار در [X](https://x.com/realchendahuang/status/2093890559874388141) منتشر شد؛ این نسخه کامل مقاله است، همراه با نقشه موقعیت پنج Harness.

واکنش اول بیشتر مردم برای انتخاب Coding Agent کاملاً طبیعی است: Claude داری، پس Claude Code؛ GPT داری، پس Codex؛ GLM داری، پس ZCode؛ DeepSeek داری، پس طبعاً اول به Harness خودِ DeepSeek فکر می‌کنی.

این نگرش در واقع کاملاً منطقی است. بزرگ‌ترین برتری بومی این است که خودش مدلش را بهتر از همه می‌شناسد.

## برتری بومی واقعی است

چه Promptی را مدل دوست دارد، چه طراحی Tool Schema پایدارترین است، متن طولانی چگونه سازماندهی شود، نسخه جدید چه توانایی‌هایی آورده، کجاها راحت‌تر لغزش می‌کند — بومی معمولاً زودتر از شخص ثالث می‌داند.

پس در محصولاتی مثل Claude Code و Codex که مدل و Harness بلندمدت با هم بهتر شده‌اند، ترکیب بومی اغلب قوی‌ترین جواب نسخه است. من مخالفت نمی‌کنم.

## اما آموزش مدل و ساختن Harness دو مهندسی کاملاً متفاوت‌اند

وقتی به مدل‌های بازی مثل DeepSeek و GLM می‌رسیم، قضیه جالب می‌شود — چون آموزش یک مدل خوب و ساختن یک Harness خوب در واقع دو مهندسی کاملاً متفاوت‌اند.

وقتی Coding Agent واقعاً راه می‌افتد، انبوهی از مسائل خارج از مدل ظاهر می‌شود:

- فایل‌ها چطور خوانده و کد چطور ویرایش شود
- Agent Loop چطور کنترل و Context چطور فشرده شود
- Cache چطور استفاده و خطای Tool Call چطور ریکاوری شود
- Subagent چطور زمان‌بندی و دسترسی‌ها چطور مدیریت شوند

درست انجام شدن این‌ها مستقیماً مشخص می‌کند که در نهایت همان مدل چقدر خوب کار می‌کند. همان مدل، در Harnessی دیگر، می‌تواند تجربه‌اش زمین تا آسمان فرق کند.

## مسئله بزرگ‌تر: مدل‌ها آنقدر سریع به‌روز می‌شوند

امروز GLM سر است؛ ماه بعد شاید DeepSeek یک Flash قوی‌تر بیرون بدهد، و مدتی بعد دوباره مدل تازه‌ای برسد.

اگر کل گردش کار کدنویسی‌ات به محصول یک شرکت بومی گره خورده باشد، عوض کردن مدل اغلب یعنی عوض کردن ابزارها و عادت‌ها هم با آن. کانفیگ‌ها، حافظه‌ها و گردش کارهایی که چند ماه درسشان داده‌ای، همه از نو.

اینجاست که ارزش Harnessهای شخص ثالث خودش را نشان می‌دهد: **می‌توانی ابزارها، Skills، MCPها، دسترسی‌ها و گردش کارهای آشنایت را ثابت نگه داری و فقط مدل زیرش را عوض کنی.** امروز DeepSeek، فردا GLM، پس‌فردا یکی دیگر — محیط کاری از صفر ساخته نمی‌شود.

## نقشه موقعیت پنج Harness

جایگاه پنج بازیگر اصلی را روشن کنیم (بر اساس تجربه من تا آخر اوت 2026):

**Pi**: فلسفه‌اش مینیمال است؛ Harness کمترین دخالت را در مدل می‌کند. سبک، سریع، مصرف Token پایین، فوق‌العاده انعطاف‌پذیر. مناسب برای زیربنای ایجنت بلندمدت خودت — ساده، تمیز، دلبخواه قابل دستکاری.

**OMP**: روی Pi ادامه می‌دهد و توانایی‌های سنگین کدنویسی مثل LSP، Debugger، Browser و AST را رویش می‌چیند؛ مثل اینکه برای ایجنت یک IDE کامل بسته‌ای. مناسب برای کدنویسی واقعاً سنگین و ناوبری پیچیده در Repo.

**DeepSeek Harness**: جلوتر از همه رفته؛ Everything is Plugin. Agent Loop، ابزارها، دسترسی‌ها، Preset و UI همگی جدا و دوباره سرهم می‌شوند. مناسب برای کسانی که با معماری ایجنت، Preset، چند-ایجنت و Runtime نسل بعد ور می‌روند. حال و هوای PTC را بیشتر امتحان کن — سریع‌تر است و Token کمتری می‌سوزاند.

**OpenCode**: در حال حاضر متعادل‌ترین گزینه؛ متن‌باز، Providerهای زیاد، اکوسیستم بزرگ، Client/Server، اپ دسکتاپ و Subagent نسبتاً بالغ. مناسب برای کسی که یک Coding Agent عمومی، بالغ و چندمدلی می‌خواهد.

**Command Code**: راهش کاملاً متفاوت است — عاشق جبران کم‌وکاستی مدل است. پارامترهای Tool Call خراب را محلی درست می‌کند؛ خواندن‌های تکراری فایل را یکسان‌سازی می‌کند؛ در نشست‌های طولانی Stable Prefix نگه می‌دارد تا Cache Hit بالا برود؛ و وقتی Context در شرف ترکیدن است Compaction انجام می‌دهد. این نگرش روی مدل‌های نوکرکار مثل DeepSeek V4 Flash و GLM-5.3 Flash بیشترین ارزش را دارد: مدل کمی ضعیف‌تر باشد، Harness جبران می‌کند.

## انتخاب من

اگر فقط انعطاف بلندمدت را ببینم، هنوز Pi را بیشتر دوست دارم. اما اگر امروز بخواهند با DeepSeek V4 Flash یا GLM-5.3 حسابی کار بکشم، جدی مزه‌ی Command Code را می‌چشم — جفتِ مدل و Harness بر اساس تسک چیده می‌شود، نه بر اساس اردوگاه.

در عصر مدل‌های باز، انتخاب مدل و Harness حالا کاملاً قابل جداسازی است. **دیگر نپرس «مدلِ کی، ابزارِ کی»، بپرس «این مدل در کدام Harness بهترین کارش را می‌کند».**
